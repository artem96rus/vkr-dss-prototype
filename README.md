# Прототип СППР выбора схем распределения товарных потоков

Прототип оптимизационного ядра системы поддержки принятия решений (СППР) по выбору схем распределения товарных потоков в распределительной сети розничного ритейлера на примере ПАО «Магнит».

Выпускная квалификационная работа, ВШБ НИУ ВШЭ, направление «Бизнес-информатика», 2026 год.

## О задаче

Прототип решает задачу выбора между двумя схемами распределения товарного потока для каждой пары «SKU – РЦ прямой доставки» на пилотном периметре Самарского региона:

- **ЦП ТРЦ** (схема №3): КА → ТРЦ → ТТ — одна перевалка на ТРЦ, последняя миля в режиме PBL;
- **Региональный пулинг** (схема №5): КА → ТРЦ → РЦ ПД → ТТ — две перевалки, магистральная фура в режиме полной загрузки FTL.

Задача формализована как задача смешанного целочисленного линейного программирования (MILP) и решается до доказуемо оптимального решения. Полное описание методологии — в параграфах 3.1–3.3 ВКР.

## О данных и параметрах

Реальные данные ПАО «Магнит» конфиденциальны и в репозитории **не публикуются**. Вместо них приложены:

- **Синтетический датасет** в `data/` с фиксированной выборкой.
- **Синтетический конфиг тарифов** `src/config_example.py` с фейковыми (но операционно правдоподобными) значениями тарифной модели.

Структура колонок, набор значений признаков и распределения подобраны так, чтобы прототип проходил все 9 фильтров и выдавал содержательные результаты MILP-оптимизации. **Числовые значения экономического эффекта на синтетических данных не совпадают со значениями в ВКР.**

### Запуск на реальных тарифах (локально, без публикации)

```bash
cd src
cp config_example.py config.py
# отредактировать config.py — поставить корпоративные значения параметров
```

Файл `src/config.py` добавлен в `.gitignore` — в публичный репозиторий не попадает. Если `config.py` отсутствует, `costs.py` автоматически использует значения из `config_example.py`.

## Зависимости

- Python 3.10+
- pandas, numpy
- openpyxl, python-calamine (чтение xlsx)
- PuLP, highspy (MILP-решатель)

Полный список — в `requirements.txt`.

## Запуск

```bash
# 1. Установить зависимости
python3 -m pip install -r requirements.txt

# 2. Запустить прототип
cd src
python3 main.py
```

Прогон занимает 1–2 минуты. По завершении:
- В консоль выводится лог фильтрации, расчёта мощностей и шести сценариев устойчивости.
- В `results/results.xlsx` сохраняется детальная выгрузка с листами «Сводная», «Декомпозиция», «Загруженность» и отдельным листом по каждому сценарию с парами и выбранными схемами.

## Описание модулей

### `main.py` — точка входа
Запускает все сценарии и сохраняет результаты в `results/results.xlsx`. Полный конвейер расчёта — в `scenarios.run_all_scenarios()`.

### `load.py` — загрузка
Функция `load_data()` читает CSV-файл ротации и XLSX-справочник мощностей, возвращает два `pandas.DataFrame`. Ищет папку `data/` относительно корня проекта и относительно расположения скрипта.

### `filter.py` — фильтрация периметра
Реализует девятиэтапную фильтрацию таблицы ротации (параграф 3.1.2 ВКР): отсекает строки вне Самарского транзитного узла, нецелевые форматы магазинов, неподходящие схемы поставки, СТМ, высокообъёмные и локальные товары, малые объёмы. Функция `aggregate_to_pairs()` сворачивает результат до уникальных пар «SKU – РЦ ПД». Выводит диагностику по каждому шагу: сколько строк осталось и какой процент от предыдущего шага.

### `distances.py` — геометрия сети
Содержит координаты шести узлов сети (ТРЦ Самара и пять РЦ ПД) и функцию `haversine_km()` для расчёта расстояний между точками по поверхности Земли. Функция `city_from_rc()` извлекает название города из имени РЦ.

### `costs.py` — удельные стоимости
Реализует формулы (2)–(4) параграфа 3.1.4: вычисляет удельные стоимости `c1_local`, `c2_local` (стоимость обработки одного паллета пары) и `c_ftl_truck` (стоимость одного магистрального рейса). Тарифные параметры подтягиваются из `config.py` (если есть) или из `config_example.py`.

### `optimizer.py` — расчёт мощностей и MILP
Содержит две основные функции:
- `calc_capacities()` — рассчитывает доступную мощность каждого РЦ ПД и ТРЦ через индивидуальные нормы потока на одно место отбора и поправочный коэффициент запаса.
- `solve_milp()` — строит и решает MILP-задачу по постановке параграфа 3.1.4 (бинарные переменные выбора схемы, целочисленные переменные числа магистральных фур, балансовое ограничение, ограничения мощности узлов и утилизации магистрали). Решатель — HiGHS через PuLP.

Функция `report_solution()` выводит развёрнутый отчёт по найденному решению: разложение целевой функции на четыре компоненты, распределение пар по схемам, загруженность узлов, число магистральных фур по РЦ, совпадение с baseline МИАС.

### `validate.py` — аналитическая сверка
Функция `validate_solution()` независимо пересчитывает все ограничения и компоненты целевой функции по выгруженному решению решателя — 20 проверок в шести группах: балансовое, мощность РЦ ПД, мощность ТРЦ, утилизация S1, утилизация S2, реконструкция целевой функции. Расхождение между значением решателя и независимым пересчётом не должно превышать 1 руб. на масштабе 100 млн руб./мес.

### `as_is.py` — стоимость по МИАС
Функция `eval_cp_column()` считает совокупные логистические затраты при назначении схем по фиксированной колонке («Действующая ЦП» или «Целевая ЦП»), используя ту же тарифную модель, что и оптимизатор. Это обеспечивает экономическую сопоставимость значений Cost(AS-IS), Cost(Целевая ЦП МИАС) и Cost(TO-BE). Функция `compare_three_way()` печатает трёхуровневое сравнение с разложением экономии.

### `scenarios.py` — сценарный анализ
Реализует шесть сценариев устойчивости из параграфа 3.2.2:

| Сценарий | Реализуемый вызов | Модификация |
|----------|-------------------|-------------|
| 0. Базовый | Опорная точка | без изменений |
| 1. Спрос +15 % | Вызов 3 — пиковый спрос | объёмы × 1,15 |
| 2. ТРЦ −15 % | Вызов 2 — омниканальность | мощность ТРЦ × 0,85 |
| 2b. ТРЦ −25 % | Порог устойчивости | мощность ТРЦ × 0,75 |
| 3. FTL +30 % | Вызов 1 — рост тарифов | стоимость FTL × 1,30 |
| 4. Киров +50 % | Вызов 4 — рост сети | объёмы РЦ ПД Киров × 1,5 |

Функция `run_all_scenarios()` запускает все шесть, для каждого вычисляя AS-IS и TO-BE. Функция `save_results()` экспортирует результаты в `results.xlsx` с тремя сводными листами и отдельным детальным листом по каждому сценарию.

### `config_example.py` — параметры тарифной модели (синтетика)
Содержит синтетические значения тарифных параметров: RATE_FTL, BETA, GAMMA, K_DOROG, CAP_TRUCK, UTIL_S1, UTIL_S2, LM_PD_KM. Реальные корпоративные значения хранятся в `config.py` (не в репозитории).
